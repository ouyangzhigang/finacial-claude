# 选股质量改造计划：让系统能推出高潜力弹性票

> 创建：2026-07-31
> 触发：用户反馈（7-30 推荐全是防御/资源/银行票，无一命中潜力股，"不然要你何用"）
> 目标：修复"用户要涨幅最高→系统却推防御票"的结构性错配，让高弹性标的能进 TopN

---

## 一、根因定位（已完成）

### R1. 回测硬门（G8）把高弹性票全杀 —— 核心矛盾
- 现状：驰宏锌锗教训写入后 `回测3项全不达标 → 踢出TopN`
- 矛盾：高潜力=高波动=回测回撤大=被证伪。刚启动/动量强的票历史胜率/回撤都不好看，全被 G8 踢出；活下来的只剩银行/石油/红利（低波动、没弹性）
- 证据：7-30 那次 37 候选仅 7 只 pass1，入场优势≥18 者全被证伪，最后推了石油/银行

### R2. G6 MCP 全挂压低置信度+仓位
- 现状：wind/akshare 的 SSL 修复已写入 server.py，但 MCP 进程未重启，修复未生效
- 后果：G6 一直"全挂"，财务/资金/龙虎榜缺失，governor 不敢给仓，全降观察/staged
- 证据：7-30 final 反复标"MCP全挂 G6强制低置信"

### R3. 候选池偏防御
- 现状：sector-analyst 在下行 regime 撒网偏防御板块（银行/资源/红利），进攻方向（成长/题材/小盘弹性）撒得少

### R4. 回测窗口与短线不匹配
- 现状：2周持有用5日回测，对短线弹性票不适用（短线票不该用2周回测硬门）

### R5. 编排者（我）机械重跑
- 现状：用户多次说"涨幅最高"，我每次机械传 riskPref:"积极" 重跑 short-term-picks，没主动改策略

## 二、改造任务（按优先级）

### T1. short-term-picks.js 加"进攻模式"分支 【核心】
- 文件：`.claude/workflows/short-term-picks.js`
- 逻辑：当 `riskPref ∈ {积极, 进攻}` 时：
  - [T1.1] G8 回测证伪 → **降级"高风险观察仓"（标注）而非踢出 0%**
  - [T1.2] 提升动量（m5/m10/m20 RPS）+ 催化（资金/龙虎榜/事件）权重
  - [T1.3] 允许追涨型标的进 TopN（标注"追涨型·须严止损"）
  - [T1.4] TopN 至少保留 2 只进攻弹性票（非全防御）
- 验证：跑一次，TopN 含进攻弹性票（非石油/银行）= 通过

### T2. MCP 进程重启（数据源生效）【需用户操作】
- 用户 `/mcp` 重连 wind / akshare / china-news 三个服务器（或重启 Claude Code 会话）
- 验证：`mcp__wind__wind_get_stock_basicinfo` 不再报 "Cannot set verify_mode" 错
- 验证：workflow 不再标"G6 MCP全挂"

### T3. 候选池定向（sector-analyst）
- 文件：`.claude/workflows/short-term-picks.js` 的 sector agent prompt
- 逻辑：进攻诉求下，撒网方向加"成长/题材/小盘弹性/次新/政策催化"，而非纯防御板块
- 验证：候选池含 ≥30% 进攻方向票

### T4. 回测窗口匹配
- 文件：`scripts/backtest_run.py` 或 risk-portfolio agent prompt
- 逻辑：2周持有→5日回测不适用；短线弹性票用更短窗口或回测降权（不直接踢出）
- 验证：弹性票不被回测直接踢出

### T5. 编排策略改进（我自己的纪律）
- 规则：用户说"涨幅最高/最具潜力"→ 优先 hot-trends 或 sentiment-trend-picks（不卡回测硬门），或 short-term-picks 进攻模式
- 不再机械重跑保守流程
- 验证：用户诉求与推荐主线匹配

## 改造详情（2026-07-31 实施）

### hard_gate.py（scripts/hard_gate.py）
- G8_回测门加 `aggressive_action: downgrade_not_top1` + `aggressive_desc`
- apply_gates() 加 `mode='normal'` 参数；mode=aggressive 时 G8 rejected → 降级观察仓不否决
- main() 加 `--mode {normal,aggressive}` 参数

### short-term-picks.js（.claude/workflows/）
- 顶部加进攻模式识别：`AGGRO = (rp==='积极'||rp==='进攻'||/涨幅|潜力|弹性|进攻/.test(rp))?'aggressive':'normal'`
- hard_gate 调用传 `--mode ${AGGRO}`
- sector 撒网：进攻模式下候选池须含 ≥30% 进攻方向票
- risk-portfolio：进攻模式回测 rejected 降级观察仓不踢出
- governor prompt：进攻模式 TopN 至少 2 只进攻弹性票 + 追涨须 T+1 复核
