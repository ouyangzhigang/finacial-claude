## 二、经过（诊断过程）

### 第一步：定位最致命根因——板块生命周期判断完全缺失

逐层排查后发现体系存在一个**完全空白**的能力层：

- `scripts/factor_engine.py` 因子层**已修**（T7.1/T7.2 把 momentum 已涨权重从 0.22 降到 0.13，新增 setup_score 将涨信号 0.17）。8-11 京东方 setup87/三花 setup92 是用新因子选的"建仓未拉升"——这层 8-11 已生效，**非当前主要矛盾**。
- **真正缺口**：没有"板块生命周期"判断——分不清板块在**启动期/发酵期/高潮期/退潮期**。
  - 8-07 电网 8-03 已涨完进入退潮期，但 sector_analyst 把它判为"下个接力板块+资金建仓未拉升+板块刚发酵"——**误判退潮为发酵**。
  - `catalyst-scanner.md` 有"个股兑现度"（近5日涨<5%未price-in/>30%透支），但**只判断个股，不判断板块整体**。个股近5日没涨≠将涨——板块退潮时个股未涨是弱势，被误判为"未price-in蓄势"。
- 确认 `regime_detector.py` 第146行只判科创50 vs 上证风格分化（颗粒度=大盘环境）；`sector-rotation-detector` skill 判宏观经济周期非题材生命周期——**两层都不是板块题材生命周期**，确实是空白。

| # | 根因 | 证据 |
|---|---|---|
| 2 | sector 越权自选宏观未定方向 | 8-07 宏观顺风=`['创新药/CXO','PCB/铜缆','稀土/小金属']`，**三路都不含电网**，但 sector 自己判断"特高压为下个接力"塞 7 只电网票 |

1. 板块生命周期判断缺失 → 退潮当发酵（根因1，最致命）
2. sector 越权自选方向 + 宏观滞后判断（根因2）
3. 缩量=建仓/撤退不分（根因3，根因1的子症）
4. 接力逻辑有但不落地建仓（根因4）
5. 手续费/滑点未建模（根因5）
6. workflow 耗时长（根因6）

## 三、应对措施与优化措施（6 方案）

### 方案1：板块生命周期探测器（核心修复，对应根因1/3）

**新建 `scripts/sector_lifecycle.py`**——判断板块4阶段：

| 阶段 | 判据 | verdict（处置） |
|---|---|---|
| 启动期 | 板块近3日异动(5日涨>3%)，龙头首板/2连，量能刚放大 | `deployable`（可选，跟风flat票=真蓄势将补涨） |
| 发酵期 | 连板梯队形成，龙头2-4连领涨跟风跟涨，量能持续放大 | `deployable`（可选） |
| 高潮期 | 龙头加速(高连板/一字)，跟风齐涨到中后排，量能见顶 | `leader_only`（只选龙头） |
| 退潮期 | 龙头滞涨/炸板，板块缩量，跟风杀跌 | `veto`（**硬否决**，8-03电网8-07即此阶段） |

**关键函数**：
- `audit_all_from_ztpool()`：从涨停池按 hybk 聚合所有活跃板块（auto 模式，主用法）
- `audit_board()`：单板块判定
- `_classify_phase()`：4阶段判定逻辑，含 sector_info 缺失时用涨停梯队为主判断的兜底
- `_find_sector_info()`：双向包含+前4字前缀匹配（解决涨停池 hybk 被截断到4字的问题，如"汽车零部"实为"汽车零部件"）

**验证结果（8-11 实测）**：
```
汽车零部  涨停7只max3连  → 发酵期/deployable
专用设备  涨停4只max2连  → 发酵期/deployable
医药商业  涨幅+1.74%+涨停3只max4连+涨多跌少 → 启动期/deployable
影视院线  涨幅+1.98%+涨停2只max2连 → 启动期/deployable
电力      涨停3只max2连  → 发酵期/deployable
医疗服务  百花6连独立妖股非板块发酵 → unclear/降权观察
电网类    涨停0只 → unclear 自动排除出候选池（无资金点火，sector找不到"涨停/大涨板块的跟风票"）
```

### 方案2：sector_analyst 加生命周期硬约束+禁越权（对应根因2/3）

**改 `.claude/agents/sector-analyst.md` Critical Rules**：
1. **只在顺风方向内撒网（硬约束，不可override）**：候选池方向必须⊆宏观 tailwinds，不得自选宏观未定方向。8-07 事故：宏观顺风=创新药/PCB/稀土，sector 越权自选"特高压接力"塞 7 只电网票。
2. **板块生命周期过滤（硬约束）**：撒网前 Bash 跑 `python scripts/sector_lifecycle.py --board <顺风板块逗号分隔> --json`，按 verdict 过滤：
   - deployable → 可选，跟风flat票=真蓄势将补涨
   - leader_only → 只选龙头
   - veto → **硬否决，一律不进候选池**（缩量=撤退非蓄势）
   - unclear → 降权观察
   - 关键句：**"个股未涨≠将涨——退潮期板块的未涨票是弱势不是蓄势"**

**改 `future-picks.js` sector prompt（第77-79行）**：接力预判前先跑 sector_lifecycle.py 判断板块阶段，只在 deployable 板块选跟风补涨票，veto 板块一票否决，每只候选标 lifecyclePhase 标签。

### 方案3：catalyst 升级板块兑现度×个股兑现度双维交叉（对应根因1子症）

**改 `.claude/agents/catalyst-scanner.md` 兑现度判断表**：

旧版只看个股近5日涨幅判断兑现度——个股未涨就判"未price-in蓄势"，但板块退潮时个股未涨是弱势不是蓄势。升级为双维交叉：

**板块兑现度表**（先判板块）：
| 板块5日涨幅 | 板块兑现度 | 处置 |
|---|---|---|
| <3% + 启动期 | 板块未price-in | 跟风flat票=真蓄势，可选加分 |
| 3-10% + 发酵期 | 板块启动 | 跟风补涨票正常选 |
| 10-20% | 板块半兑现 | 跟风票补涨空间收窄，降权 |
| >20% + 高潮期 | 板块透支 | 只选龙头，跟风票不选 |
| 龙头滞涨/炸板 | 板块退潮 | 整板块否决，个股未涨=弱势非蓄势 |

**双维交叉核心判定**：
- 个股未涨(<5%) + 板块启动期 → **真蓄势将补涨**（加分，TopN主推）
- 个股未涨(<5%) + 板块退潮/高潮期 → **弱势滞涨**，不是蓄势，降权或剔除（8-07电网跟风票即此误判）
- 个股未涨 + 板块5日涨>15%(半兑现) → 个股跑输板块=弱，不选

**改 `future-picks.js` catalyst prompt**：加板块兑现度判断步骤，对候选票所属板块跑 sector_lifecycle.py 取 verdict，退潮期板块不论催化多硬都不选。

### 方案4：接力落地建仓（对应根因4）

**改 `future-picks.js` 推理锁定 governor prompt（5c）**：

按 lifecyclePhase + boardPhaseVerdict 定仓：
- 板块 deployable（启动/发酵期）+ 个股 flat 未涨 + setup 高 + 多信号共振 → **TopN主推，标正常建仓(5-15%)，不标观察仓0%**
- 仅当板块阶段 unclear/资金信号缺失/形态未确认时才降观察仓0%
- 板块 leader_only（高潮期）降仓(3-8%)+标"高潮追涨，严格止损"
- 板块 veto（退潮期）不入 TopN

**病根**：旧版把"资金未确认"一刀切降观察仓，导致真正将涨的发酵期接力票缺席 TopN，推的反而是已退潮票。8-11 三花智控发酵期跟风票被标"观察仓0%"即此病根。现在用板块生命周期作建仓落地依据，deployable 板块跟风票敢推敢建仓。

同时改 `future-picks.js` 推理验证 prompt（reasonedPicks 输出加 lifecyclePhase + boardPhaseVerdict 字段，从 sector 证据继承）。

### 方案5：forecast_tracker 手续费/滑点建模（对应根因5）

**改 `scripts/forecast_tracker.py`**——加完整 A 股交易成本模型：

| 成本项 | 费率 | 说明 |
|---|---|---|
| 佣金 | 万2.5，最低5元/笔 | 双边（买+卖各一次），1万账户小额交易最低5元占比高 |
| 印花税 | 卖出千1 | 单边 |
| 滑点 | 买入+0.3% | 理想价之上，反映真实成交价高于盘中低点 |

**新增字段**：buyPrice（含滑点买入价=理想价×1.003）、feeDragPct（手续费拖累%）、netActualChangePct（扣费后净涨幅）、netAlphaPct（扣费后净超额）。

**新增 `recheck` 子命令**：用已存储的 actualChangePct（到期日毛涨幅）反推费用，不重新取价（避免用今日价污染到期日兑现），重算旧记录的扣费后净收益。

**诚实重算结果**：
```
forecast_tracker: 重算 26 条已验证记录的扣费后净收益
  毛口径命中率 16/26 → 扣费后命中率 57.7% (15/26)
  平均毛alpha +2.10% → 扣费后净alpha +1.59% (手续费拖累 0.50%)
```

**关键解读**：
- 1 只票因手续费从"跑赢大盘"变成"跑输"（毛口径16只→扣费后15只）
- 扣费后命中率仍 >50% 且净 alpha 为正 → **选股能力扣费后依然有效**，不是靠大盘 beta
- 0.50% 拖累对 1万账户 25% 仓位（2500元）是真实成本——这正是用户说的"微赚实亏"的数据证据

**操作卡改进**：买入区间注明"实际成交价约+0.3%滑点"，止损位同步上移。

### 方案6：workflow 瘦身 8agent→7agent（对应根因6）

**改 `future-picks.js`**——合并阶段3（推理验证 governor）+阶段4（潜力锁定 risk-portfolio/governor）为单个"推理锁定"governor：

- 旧：5阶段8agent（预判假设→证据收集4并行→推理验证governor串行→潜力锁定governor串行→跟踪兑现）
- 新：4阶段7agent（预判假设→证据收集4并行→**推理锁定governor合并**→跟踪兑现）
- 省1次串行等待，阶段2保持4并行（结构合理不动）
- 目标耗时 <30分钟（原52分钟）
- 已验证 JS 语法 OK + LF 行终止符（避免 Workflow 权限钩子报"script contains control characters"）

## 六、总结与教训

### 诚实认账（不狡辩）

1. **推退潮票是判断失误，不是"市场难测"**——体系压根没有"板块生命周期"判断层，把退潮当发酵，这是实打实的失误，不是甩锅给市场的借口。
2. **手续费必须建模**——"你以为不需要手续费嘛"对1万账户是真实成本，"微赚14元"扣费后实亏，旧收益测算是虚高的。
3. **买入价不能理想化**——盘中低点当买入价，实际开盘跳空+滑点成交价更高，"你确定能以那么低的点买的啊"。
4. **过度保守让将涨票缺席**——发酵期跟风票被标"观察仓0%"，真正将涨的没进可部署清单，推的反而是已退潮的，结构性矛盾。
5. **"已涨当将涨"是老毛病**——8-03 涨完 8-07 才推，这个时点错配一直没改干净，本次从板块生命周期层根治。

### 不敢承诺的

**不承诺"下次一定推到涨的"——那是糊弄。** 改的是**判断框架**：
- 退潮票不会再被当"刚发酵"塞进来（sector_lifecycle veto 挡住）
- 收益测算会诚实扣费（forecast_tracker 手续费建模）
- 发酵期跟风票敢进可部署清单（接力落地建仓）

准不准，下次跑完看 `forecast_tracker` 的扣费后命中率（当前诚实基线：57.7%/净alpha+1.59%）。

### 体系级教训

| 教训 | 落地措施 |
|---|---|
| 缺板块生命周期层→退潮当发酵 | sector_lifecycle.py 4阶段判定，veto硬否决 |
| 个股兑现度单维→未涨误判蓄势 | 板块兑现度×个股兑现度双维交叉 |
| sector越权→宏观未定方向塞票 | 硬约束候选池⊆宏观tailwinds |
| 过度保守→将涨票缺席TopN | deployable板块跟风票敢推敢建仓5-15% |
| 手续费未算→收益虚高 | 佣金万2.5最低5元+印花税千1+滑点0.3%建模 |
| workflow串行太多→52分钟 | 8agent→7agent，推理验证+潜力锁定合并 |
